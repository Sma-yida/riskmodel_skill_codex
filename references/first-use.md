# 交互与需求确认

与 [SKILL.md](../SKILL.md) 配合使用。本文件维护固定交互节点与格式；各环节指南维护参数和推荐问候选，不另设新老用户分流。

## 固定节点与路由

正常路径：**明确需求 → 参数预检 → 标准需求确认 → 用户确认 → 写入核对并执行 → 结果/报告 → 环节指引＋推荐问**。

| 输入或状态 | 处理 |
|---|---|
| 首次触发，目录/环境/数据尚未准备 | 先只读检查，直接给具体准备清单；确认后完成准备，说明数据路径，再给指引和推荐问。不先问是否需要方案 |
| 已就绪，用户明确指定环节、默认方案或参数 | 直接预检并给标准需求确认，不再插入路线选择 |
| 已就绪，但只说“开始/继续”“接下来做什么”，没有可继续的有效授权 | 读取项目状态，给固定环节指引和推荐问；选择后才生成需求确认 |
| 非法、歧义、不支持或缺必要信息 | 简述具体问题，给纠正候选；选择后重新校验，再给标准需求确认；仍有问题继续补缺口 |
| 已确认的范围尚未结束 | 按原范围继续，不在各环节之间插入推荐菜单或重复确认 |
| 帮助、参数说明、状态/报告查询、明确停止 | 直接回答/读取/停止，不套建模确认，不先安装环境 |

**推荐问选择、纠正选择与需求确认是不同节点。** 前两种只表达需求，不写业务配置、不启动环节；清单确认才授权。不要使用“选择此推荐问即可直接执行”的捷径。一次标准清单可以确认多个环节；只执行其中范围。

## 首次准备

先核对用户指定/当前项目的目录、环境候选、数据及已有进度；检查与预览不提前创建目录或安装。用户指定优先，选择和验证方法见 [环境指南](setup.md)。数据与明确业务范围均可核对时，准备项可合并进同一需求清单；否则先确认准备。

```text
我可以完成数据质量分析、清洗切分、特征筛选、训练和评估。当前需要先准备建模项目。

需求确认
本次操作：创建工作目录和建模环境，完成验证。
1. 工作目录：〈拟建目录的绝对路径〉［拟新建］
2. 建模环境：〈实际检查结论〉。拟建 riskmodel-py39，安装至〈绝对路径〉，采用〈可行方式〉，需要联网下载。
3. 建模数据：尚未发现，准备后放入〈工作目录/data/ 的绝对路径〉。

选项：确认以上准备并联网安装（推荐）／暂不准备
```

已有环境则写实际解释器及验证状态，不推荐重装；可离线创建则写实际离线方案。未完整检查不能写“验证通过”，没有安装前提不能承诺可以创建。首次准备/绑定、切换或异常时才展示环境和目录；后续从本项目记录恢复并检查，正常需求清单只展示业务环节和参数。

准备完成只总结实际结果，例如：

> 工作目录已创建，建模环境已验证通过。请按照指定格式准备数据，放入〈工作目录/data/ 的绝对路径〉。

接着给下节的环节指引及“数据已放好，……”推荐问；不默认展开文件格式、基础列或标签口径。用户询问或格式检查失败时才说明相关要求。数据已在位不要求再次上传；准备失败说明已完成部分和失败处，不使用成功话术。

## 环节指引与推荐问

固定格式，执行说明用一句话说明作用和输出，不展开参数表：

```text
执行环节指引
当前状态：数据清洗切分已完成。
下一步操作：特征筛选。
执行说明：按 IV、PSI、缺失率及相关性等规则筛选特征，输出入选名单与筛选报告。
环节参数说明：使用手册待补充。

推荐问（选择后生成需求确认）：
1. 使用默认参数完成特征筛选。
2. 将 IV 阈值设为 0.05、PSI 阈值设为 0.1，进行特征筛选。
3. 启用 Null Importance，Top N 设为 300，进行特征筛选。
4. 重新进行数据清洗切分，改用随机切分，测试集占比 0.25。
```

以上选项是假设普通规则筛选且前置有效时的候选，不保证参数变体更优。每次按实际状态与分支检查：

- 第一项通常为下一环节默认方案；第二、三项是该环节可生效的具体参数变体；第四项可重做上一环节并调整公开参数。没有适用前置或参数就减少选项，不硬凑四个；没有上一环节时不提供回跳。
- 推荐问是一句可独立提交的用户请求，写清环节、参数和值。不要用“了解一下”“先帮我设计方案”“查看报告”等泛泛请求占主要选项。参数说明另作按需帮助。
- 参数名和值以公开接口为限；数字候选是可选设定，不是最优承诺。日期、渠道、特征和模型名称必须来自当前数据/产物；没核实就不编造。用户原先已明确且仍适用的约束须保留，推荐问若提出不同设定必须显式写出变动。
- 有人工特征名单时，阈值筛选选项需明确“清空人工名单并……”才能生效；有训练复现文件时，不能推荐会被其覆盖的参数并声称生效。Null Importance 的现有辅助文件、HPO 和评分卡评估等分支限制依对应指南核对。
- 未选中的候选不改变配置。选择后读取当前配置，形成变更并预检，再展示标准清单；用户确认该清单后才写入并运行。推荐问尚有缺口时先补齐，不把示例占位符写入参数。
- 首次数据未在位时，可给“数据已放好，使用默认参数进行数据质量分析”等问法；选中后仍核查文件。没有有效分析结果时，不能推荐“跳过质量分析直接清洗”；已有有效结果时可直接清洗且不重复分析。
- 评估后已无第六环节：给结束或重做已支持环节的选项。评分卡评估没有可调整且生效的评估参数时，给生成摘要和返回训练等少量有效选项。

手册位置暂用纯文本“环节参数说明：使用手册待补充”，不伪造链接或可点击跳转。用户询问参数时读取本环节指南回答；后续有真实手册及章节锚点，再将这一行接为入口，不默认输出整张参数表。

首次数据分析候选：
1. “数据已放好，使用默认参数进行数据质量分析。”
2. “数据已放好，进行数据质量分析，不生成数据质量 Excel。”
3. “数据已放好，进行数据质量分析，不保存中间统计 CSV。”

## 标准需求确认

固定格式：**中文含义（完整公开参数名）：准确值［来源］**。清单只写动作、环节和参数；必要的准备或执行影响各用短句，不穿插功能教学。默认参数也展示实际值，不能仅写“默认值”。

来源规则：
- `［默认］`：未另行指定且等于该参数的模板默认值；明确使用默认方案时也用此标记，恢复项显示旧值 → 默认值。新项目不写“沿用/初始默认”。
- `［用户修改］`：本次明确指定的参数，包括选择具体参数推荐问；值未变化也不虚构旧值变化。
- `［保留当前］`：用户未要求更改、当前值又不同于模板默认值；不能标成默认或偷偷重置。
- `［联动］`：脚本因本次参数自动改变的值；须一并展示。

“使用默认参数”明确指**本环节生效分支的模板默认值**。有自定义配置时，清单写明将恢复哪些值；仅这一环节恢复，不重置其他环节。通过现有参数脚本设置公开参数，不覆盖整份 JSON。比例/随机切分不要提交不生效的三个日期范围，否则脚本会联动为 date_range；默认训练为 LightGBM、关闭寻优，不将其他算法的参数混入生效清单。复现文件覆盖仍需先解决，不能以恢复模板冒充恢复实际行为。用户说“其他不变”时保持当前值，不执行默认恢复。

示例：当前清洗配置等于模板，用户要求“重新清洗，随机切分”。

```text
需求确认
本次操作：仅运行数据清洗切分。

1.「数据清洗切分」
   - 数据切分方式（split_method）：random［用户修改］
   - 测试集占比（test_size）：0.2［默认］
   - 随机种子（random_state）：42［默认］
   - 保留渠道列表（channel_keep_list）：[]［默认］
   - 缺失值填充值（fill_val）：-9999［默认］

选项：确认执行以上需求（推荐）／暂不执行
```

实际存在旧产物时才加“将替换本环节结果，并使相关下游结果失效”。按顺序列出本次涉及的所有环节，不把无关算法参数、标签文字或已经绑定的目录环境放进清单。覆盖复现文件、额外拟合、硬约束无法满足等影响按实际说明。

清单包含所有指定/恢复/联动项及当前分支关键生效值；完整配置入口供按需核查，不重复附长表。准确保留 0.2211、布尔、完整列表和特征名；长列表可链接本次准确内容，不用省略号代替参数。确认前预检 → 复用同一变更写入 → 读回核对的顺序见主入口；“修改拟定参数”不等于确认前写入配置。

非法值的固定路径示例：`iv_thresh=1.5` → 说明支持范围 0～1，给“改为默认 0.02”或其他有依据的候选 → 用户选择 → 生成完整特征筛选清单 → 用户确认 → 执行。不要将“同意纠正”当成最后的执行确认；清单仍有错误时再次更新，直到确认无误。

## 数据约定：按需说明

主数据为 data.csv、data.parquet 或 data.feather，同名只留一种；基础列为 id/date/label/channel，外部 oot_* 可选。检查不符时只说明具体缺口，不自动删文件、改列名或转换业务数据。外部 OOT 的实际日期以数据为准。

后台固定把 label=1 计为坏样本、0 计为好样本，没有可切换方向的公开参数。正常交互按既定格式使用，不追问含义、不将其放入推荐问/需求确认、不主动调用标签记录选项。用户明确说明编码相反、或已有材料显示冲突时，说明不符合固定格式并等待其提供符合要求的数据；不能假装记录标签文字就完成转换。旧项目的 label_meaning 字段只保留兼容，不是建模配置，也不作为每次确认的前置条件。

## 选项工具与确认对应

优先用宿主实际提供且允许用途的工具。`request_user_input_async` 使用 `questions`，每项 `title` 和字符串 `options`；自由输入由工具提供，不增加“其他/自定义”。其他工具仅在真实可用且用途允许时使用；不为按钮另建前端。无合适工具则编号展示，保留自由回复。

- 推荐问通常最多四项；清单确认通常“确认执行以上需求／暂不执行”两项。选项须自含动作，不只问“可以吗”。宿主有数量限制时减少候选，不拆成多轮菜单。
- 问题明确属于“选择需求”“选择纠正”还是“确认清单”，不要把这几类混在一个问题里。确认安装/保存配置不扩大为训练授权。
- 预选、未回复、超时或工具调用成功都不是同意。等待时可独立读取，不进行依赖回答的写入/安装/业务执行。
- 异步回复只对应原问题的目录、范围和参数；旧问题回答不授权新方案。无标识的“确认/1”指向不唯一时才澄清。用户修改已展示方案时重新预检和展示变化，再确认；纯确认且方案未变则执行。

## 执行完成

先报告本次实际完成范围、关键结果/问题和报告链接，再按固定格式给下一环节指引与推荐问。报告未生成就如实说明，不编造文件。执行失败先给修正选项，修正后重新进入需求确认；执行器/依赖缺陷不归咎于用户数据。

已确认多环节任务正常继续，范围内只报告实际进度与结果，不中途询问下一步。用户已明确下一步需求时直接进入其需求确认；无新需求时才使用指引。程序成功、用户条件满足和适合业务使用分别判断，不以 succeeded 代替结论。
